# Security Policy & Terms of Use

## ⚠️ Important Warning: Platform Policies & Account Risk

The **Zip Bomb Maker Project** is an automated framework designed strictly for authorized, defensive testing, security research, and filesystem benchmarking. 

Please be aware of the following platform risks:
* **GitHub Terms of Service:** Utilizing this tool to generate, store, or distribute payloads intended to disrupt, degrade, or deny service to third-party infrastructure violates GitHub’s Acceptable Use Policies.
* **Risk of Account Action:** Running workflows or hosting repositories that are flagged for malicious distribution or active weaponization can result in your GitHub account being **restricted, suspended, or permanently banned** by GitHub administration.
* **Run at Your Own Risk:** The maintainers of this project are not responsible for automated infrastructure blocks, platform bans, or system degradation caused by deploying or executing this code within your CI/CD environments.

## 🔍 Reporting a Vulnerability

If you discover a security flaw within the implementation of the generator script itself—such as an unintended local resource leak or a breakdown in generation safety limits—please report it responsibly.

### Reporting Process

1. **Do Not Open a Public Issue:** To prevent exploitation or unintended disruption, do not use public GitHub Issues to report design flaws or logic errors that compromise the safety boundaries of the script.
2. **Submit a Private Report:** Send a detailed breakdown of the vulnerability, along with proof-of-concept configuration details, directly to the project maintainers via the security advisory portal or at **[INSERT PRIVATE CONTACT EMAIL]**.
3. **Response Timeline:** A maintainer will acknowledge receipt of the report within 48 hours and work to provide an architecture fix or mitigation path within 14 business days.
